## 2026-09-27: Android — in-app game data setup, CI APK build, upstream fixes

This fork imported fadi-labib/Generals-Android (fast-forward; its history already
contains EA's release, TheSuperHackers, GeneralsX and the iOS port). Work since:

### APK build in CI

- `release-android.yml` now also runs on pushes to the Android port branch and uploads
  the APK as a workflow artifact (the Release step stays tag-only).
- **Configure was broken upstream since 2026-07-08.** The DXVK submodule was bumped to
  fadi-labib/dxvk `78c2ce1b` (gate Turnip on `/dev/kgsl-3d0`), which edits
  `vulkan_loader.cpp` after the fork already carries the Android patch. `dx8.cmake`'s
  idempotency check (`git apply --reverse --check`) then failed on that one file, so
  configure tried to apply `Patches/dxvk-android.patch` a second time and aborted.
  Root cause fix: regenerate the patch as the fork's full Android delta
  (`46a3bc01..78c2ce1b`). Verified both paths: reverse-check passes on the pinned commit,
  and the patch still applies cleanly to the unpatched base.

### In-app game data setup (`SetupActivity`)

The launcher now starts the game when data is present, otherwise offers:

- **Download from Steam** — the user signs in to their own account; JavaSteam 1.8.0's
  depot downloader fetches app 2732960's Windows depot (what `scripts/get-assets.sh` pulls
  with steamcmd). Steam Guard via mobile approval, app code or email code. Credentials and
  the session token stay in memory only.
- **Import from folder** — `ACTION_OPEN_DOCUMENT_TREE`, no storage permission; skips
  Windows-only files; accepts the install folder or a parent up to two levels above it.
- **Buy on Steam** — store page.

Data goes to `<external app files>/GeneralsZH`; `/sdcard/GeneralsZH` (adb push) still wins
when present. A `.gx_setup_complete` flag guards against an interrupted download/copy
leaving `INIZH.big` behind without the rest. The directory reaches `SDL3Main.cpp` through
`GX_GAME_DATA_DIR` (set with `Os.setenv` before SDL loads). The APK bundles the Liberation
fonts (`stage-fonts.sh`), copied next to the data because the engine loads `fonts/*.ttf`.

JavaSteam declares its chunk decompressors `compileOnly`, so the app adds `org.tukaani:xz`
and the `zstd-jni` **aar** (the jar only carries desktop natives).

CI run 3 got through the whole native build (libmain, DXVK, adrenotools) and failed at
`compileDebugJavaWithJavac`: `package okhttp3 does not exist`. JavaSteam's POM declares
OkHttp (and all its other deps) with runtime scope, so Gradle keeps them off the compile
classpath; the earlier local javac check had used every runtime jar and hid it. Fixed by
using JavaSteam's default `SteamClient()` configuration instead of a custom OkHttp client
(adding OkHttp directly would pull `okhttp-android` next to JavaSteam's `okhttp-jvm`).
The local check now compiles against exactly the compile-scope jars. The zstd-jni aar's
arm64 library is already 16 KB aligned.

Validation so far: Java sources compile against the Android 14 framework
(Robolectric `android-all`), SDL 3.4.2's Java glue and JavaSteam 1.8.0 with no warnings.
Not yet run on a device.

### Upstream fixes ported (open PRs on fadi-labib/Generals-Android)

- **#24** (KLCLAU, cherry-picked): skip Turnip on Adreno 8xx (Snapdragon 8 Elite / Galaxy
  S25-S26), where the ad07xx Turnip build enumerates zero devices; the stock driver already
  has Vulkan 1.3 + BCn there. `GENERALSX_NO_TURNIP=1` forces the stock driver anywhere.
  Upstream issue #23.
- **#25** (KLCLAU): 16 KB ELF page alignment. Taken as-is for the DXVK meson cross file and
  `build-adrenotools.sh`. For the main CMake build we use the NDK's
  `ANDROID_SUPPORT_FLEXIBLE_PAGE_SIZES=ON` instead of setting `CMAKE_SHARED_LINKER_FLAGS`
  in the preset: a user-set cache value replaces the toolchain's `*_LINKER_FLAGS_INIT`, which
  would drop the NDK's default linker flags. `package-android-zh.sh` now fails the build if
  any library we build has LOAD alignment below 0x4000 (prebuilt Turnip and NDK libc++ only
  warn), so CI proves the result.

### C&C Online

Already wired: `cmake/gamespy.cmake` sets `GAMESPY_SERVER_NAME=server.cnc-online.net`
(TheSuperHackers), and the Android build compiles the GameSpy SDK. The SDK is now fetched

### C&C Online: "Online" could never reach the login screen

Traced the online entry path without the C&C Online launcher (which on PC redirects DNS):

- `StartPatchCheck()` first resolves `servserv.generals.ea.com`. It has no DNS any more, so
  `cantConnectBeforeOnline` was set, the "cannot connect" box shown, and the game returned
  to the menu. Every Android (and launcher-less) attempt ended there.
- `GSI_DOMAIN_NAME` only rewrites hostnames the GameSpy SDK builds. Some of those don't exist
  on C&C Online: `ccgenzh.ms6.server.cnc-online.net` (server browser),
  `ccgenzh.master.…` (QR2 heartbeats), `ccgenzh.available.…` — verified NXDOMAIN, while
  `master.`, `peerchat.`, `gpcm.`, `gamestats.`, `http.` all resolve.

Fix, mirroring the C&C Online client's own redirect table (xan105/CnC-Online, MIT,
`src/online.h`: servserv → `http.server.cnc-online.net`, `ccgenzh.ms6` → `master.`):
new `OnlineServiceHosts.h`; `cmake/gamespy.cmake` passes `RTS_GAMESPY_SERVER_NAME` to game
code; servserv lookup, base URL, gamestats, players-online and peerchat local-IP hosts use
it; before `peerInitialize()` the SDK's own override hooks (`qr2_hostname`,
`GSIACHostname`, `SBOverrideMasterServer`) point at the master host. Standalone compile test
against the SDK headers with and without the define prints the expected hosts.

Not reachable from the build environment (network policy), so the servserv files under
`http.server.cnc-online.net` could not be fetched to confirm the path; needs an on-device
test. Known remaining gap: the SDK hardcodes peerchat port 6667 (the PC client retries
16667 when an ISP blocks 6667); on such mobile networks use Wi-Fi.

### Patch check and map packs on non-Windows

- No installer writes `registry.ini` on Linux/Android, so `Version`/`MapPackVersion` were
  missing: the patch check asked for `english-0.txt` / `maps-0.txt` and
  `hasWriteAccess()` failed. The POSIX WWDownload shim now falls back to the retail 1.04
  installer values (0x00010004 / 0x00010000); `GetRegistryVersion()` (reported via
  `peerSetTitle`) defaults to 0x00010004 instead of 65536.
- Servserv patches and map packs are Windows installers applied by `Launcher.exe` after the
  game quits. Non-Windows builds now ignore patch offers (logged) instead of quitting or
  blocking online on a mandatory patch; the port updates through its own releases.

### Touch and text input

Touch was already complete on Android (`GX_TOUCH_UI`: tap, drag-box, long-press right-click,
double-tap, two-finger pan with edge scroll, pinch zoom). The on-screen keyboard appears for
entry fields (`SDL_StartTextInput`). Password fields (`EntryData::secretText`, e.g. the online
login) now request `SDL_TEXTINPUT_TYPE_TEXT_PASSWORD_HIDDEN` with autocorrect off, restarting
text input when focus moves between normal and password fields.

### Launcher: maps and online account

With game data present the launcher now shows Play / Add maps / C&C Online account /
Re-import game files instead of starting immediately. "Add maps" copies a map folder (or a
folder of map folders) into `files/GeneralsX/GeneralsZH/Maps`, the engine's user map dir
(`$XDG_DATA_HOME/GeneralsX/GeneralsZH/` + `Maps`), which is also where lobby map transfers
land.
